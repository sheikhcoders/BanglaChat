## 2026-07-30 - Accessible Bilingual Repository-as-an-Interface Design

**Learning:** In uninitialized or early-stage repositories, the repository structure and documentation function as the developer interface (Repo-as-an-Interface). Applying localization and accessibility principles to metadata files (like README and Pull Request templates) ensures an inclusive onboarding experience. This includes wrapping emojis in semantic `<span role="img" aria-label="...">` wrappers and using precise bilingual terminologies (such as "পুলের রিকোয়েস্ট" for Pull Request in Bengali while strictly avoiding incorrect terms like "পুলগি") to maintain clarity and trust.
**Action:** Always wrap emojis in accessible semantic markup and use standard, developer-approved localized terminology across all repository files.

## 2026-08-03 - Nudging Accessibility and UX in Feature Requests

**Learning:** Designing structured, bilingual feature request issue templates can proactively nudge community contributors to think about accessibility and user value from the very start. By explicitly including a prompt for "Accessibility & UX Impact" in both English and Bengali, we embed inclusive design requirements into the ideation phase, ensuring that accessibility remains an integral pillar of the project's features.
**Action:** Include structured UX/accessibility sections in feature specification templates, issue templates, and product briefs to build an accessibility-first culture.
