## 2026-11-03 - CI/CD Workflow Hardening & Least Privilege
**Vulnerability:** Default CI workflow configurations lacked explicit minimal permissions, persisted checkout credentials to runner storage, lacked job execution timeouts, and attempted package installation in an uninitialized repository lacking package.json.
**Learning:** Default GitHub Actions runners grant broad repository write scopes unless explicitly restricted with `permissions: contents: read`. Additionally, `actions/checkout` defaults to persisting the GITHUB_TOKEN locally in `.git/config`, posing exposure risks if untrusted build steps execute. In minimal or uninitialized repositories, npm caching and execution steps fail if lockfiles/manifests are missing.
**Prevention:** Explicitly define top-level read-only permissions (`permissions: contents: read`), set `persist-credentials: false` on checkout steps, enforce 15-minute `timeout-minutes` on jobs, and guard package-dependent steps with `hashFiles('package.json') != ''`.
