## 2026-11-02 - CI/CD Least-Privilege Scoping and Credential Protection

**Vulnerability:** Default GitHub Actions workflows execute with implicit permissions and write tokens persisted into local `.git` metadata (`persist-credentials: true` by default in `actions/checkout`), potentially allowing compromised scripts or build steps to access or abuse repository write credentials. Workflows also lacked job timeouts and failed in uninitialized repository states.
**Learning:** In repositories with Next.js GitHub Pages deployments and Node.js CI, workflow jobs must strictly adhere to least privilege: enforce top-level read-only permissions (`contents: read`) or targeted job permissions (`pages: write`, `id-token: write` on deployment jobs only), disable credential persistence on checkout steps (`persist-credentials: false`), bound execution time with `timeout-minutes: 15`, and guard dependency/build commands against missing `package.json` in minimal or uninitialized repositories.
**Prevention:** Always audit new and existing workflows for explicit permission blocks, disabled checkout token persistence, execution timeouts, and dependency existence checks before running `npm ci` or caching.
