## 2026-07-28 - GitHub Actions Supply Chain Security and Runner Hardening
**Vulnerability:** Workflows were configured to run with mutable action version tags (e.g., `@v4`, `@v5`) instead of immutable commit SHAs. Additionally, jobs lacked explicit read-only permissions and timeouts, which exposed the runner environment to token leakage, unauthorized modifications, and infinite execution hangs (Denial of Service).
**Learning:** Tag-based references in GitHub Actions can be silently mutated or hijacked if an upstream action is compromised (supply chain attack). Without explicit permission scopes, GHA tokens default to overly permissive credentials, potentially exposing sensitive repository access. Lacking timeout configurations can lead to hanging processes draining billable workflow minutes.
**Prevention:** Always pin core and third-party GitHub Actions to immutable 40-character commit SHAs, accompanied by version comments for readability. Enforce global or job-level `permissions: contents: read` to maintain least privilege, and set explicit job-level `timeout-minutes: 15` to limit execution abuse. Use step-level manifest existence checks post-checkout to gracefully bypass uninitialized build states.
