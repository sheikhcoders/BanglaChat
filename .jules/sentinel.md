## 2026-07-20 - CI/CD Supply Chain Hardening & Uninitialized Repository Mitigation
**Vulnerability:** In uninitialized repositories lacking application code, typical CI pipelines run into 'Dependencies lock file is not found' errors. Standard mitigation patterns often try to skip builds entirely but miss protecting actions against third-party dependency compromises or supply chain vulnerabilities. Additionally, missing timeout policies and overly permissive run environments create attack surfaces for resource exhaustion and permission abuse.
**Learning:** Checking package.json existence post-checkout at step-level allows safe bypass of setup and installation tasks. Pinning all actions using full 40-character commit SHAs blocks upstream supply chain tampering. Explicit global permission definition restricts token permissions to minimum read-only scope, and job-level overrides restrict deployment access specifically.
**Prevention:** Always pin third-party actions to immutable SHAs, enforce strict global read-only permissions, implement job-level timeouts, and protect pipelines in uninitialized states using step-level file checks rather than job-level hashFiles before repository checkout.
