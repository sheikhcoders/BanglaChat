## 2026-07-23 - Hardening CI/CD Workflows for Uninitialized Repositories
**Vulnerability:** Supply chain attacks via third-party GitHub Actions, privilege escalation through overly permissive global GHA token permissions, and workflow execution failures ("Dependencies lock file is not found") on uninitialized repository states.
**Learning:** Default GitHub Actions templates often request broad global permissions, omit execution timeouts, use mutable tags (like `@v4`), and assume package manifests exist. This exposes runners to supply chain compromise, infinite execution loops (DoS), and predictable build failures prior to actual project initialization.
**Prevention:** Pin all third-party actions to immutable 40-character commit SHAs, restrict global and job-level permissions strictly to `contents: read` unless specified otherwise, enforce a standard `timeout-minutes: 15` threshold, and introduce a conditional step-level check for package manifests (like `package.json`) post-checkout to cleanly bypass downstream package tasks.
