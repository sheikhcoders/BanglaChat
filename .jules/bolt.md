# Bolt's Journal - Critical Learnings

## 2026-07-27 - Dual Concurrency Patterns and Manifest Guards in Uninitialized Repositories
**Learning:** In Next.js deployment workflows, `cancel-in-progress` must remain `false` to ensure production deployments are not interrupted midway, which could lead to inconsistent deployment states or broken pages. Conversely, in generic validation workflows like Node.js CI, setting `cancel-in-progress: true` is highly recommended to immediately terminate outdated commits on the same branch and reclaim precious CI runner time. Additionally, in uninitialized repository environments, standard package-manager detection or installation steps will predictably crash with 'Dependencies lock file is not found'. A simple step-level check for `package.json` immediately after checkout allows workflows to cleanly and successfully bypass build activities without causing false-alarm build failures or consuming unnecessary runner seconds.
**Action:** Always configure `cancel-in-progress: false` on production/deploy workflows and `cancel-in-progress: true` on validation/test workflows. Implement early post-checkout checks for `package.json` existence to conditionally guard all subsequent actions when working with uninitialized codebases.
