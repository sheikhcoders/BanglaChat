## 2025-04-03 - CI Optimization and Robustness for Uninitialized Repositories
**Learning:** In repositories that are early in their lifecycle or lack certain manifests (like `package.json`), standard CI workflows for Node.js or Next.js can fail early. Adding `paths-ignore` for non-code files (like `README.md` or `.jules/**`) provides a 100% compute saving for those commits. Implementing "Bootstrap Guards" like `if: hashFiles('package.json') != ''` and creating fallback directories (e.g., `./empty_out`) for artifact uploads ensures the CI pipeline remains green and robust even before the project is fully initialized. Dynamic package manager detection ensures the workflow is compatible with `pnpm`, `npm`, and `yarn` while optimizing for the fastest available tool. Correctly using `GITHUB_ENV` to set artifact paths dynamically is more reliable than using `hashFiles` on directory names.
**Action:** Always implement `paths-ignore` for documentation and journal files. Use dynamic package manager detection for robustness. Use conditional step execution based on the presence of manifest files and dynamic environment variables for artifact paths to maintain CI stability in evolving or uninitialized environments.
