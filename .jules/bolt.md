## 2026-07-21 - [CI Workflow Optimization and Hardening for Uninitialized Repo]
**Learning:** In uninitialized repositories lacking a functional application or a package.json, standard CI builds and test suites will consistently fail with 'Dependencies lock file is not found' or missing module errors. To prevent wasting runner minutes and avoid failing status checks on non-code changes, workflows must ignore changes to documentation/journals and use step-level existence guards for package.json (rather than job-level hashFiles, which are evaluated before the checkout step) to gracefully skip build/deploy tasks.
**Action:** Always implement `paths-ignore` on docs and `.jules/**`, configure step-level package.json existence checks immediately after actions/checkout, and conditionally guard all subsequent dependencies, linting, testing, and building tasks.
