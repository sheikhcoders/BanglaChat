## 2026-04-25 - CI/CD Supply Chain and Reliability Gaps

**Vulnerability:**
1. Workflows were using tagged versions (e.g., `@v4`) for actions, which are mutable and susceptible to supply-chain attacks if a tag is moved to a malicious commit.
2. Missing job-level permissions and timeouts could allow for privilege escalation or resource exhaustion.
3. CI workflows failed in an uninitialized repository state due to missing manifest files, creating a reliability gap and "red" build noise.

**Learning:**
Default GitHub Actions workflows generated by platforms often lack security best practices like SHA pinning and minimal permissions. In early-stage or uninitialized repositories, workflows must be hardened to fail gracefully or skip steps when dependencies are not yet present.

**Prevention:**
1. Always pin actions to full 40-character commit SHAs.
2. Set explicit minimal permissions (`contents: read`) and `timeout-minutes`.
3. Use `hashFiles` or existence checks to guard execution steps in uninitialized states.
